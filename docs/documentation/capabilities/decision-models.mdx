title: 'Decision Model Completions'
description: 'Ask a decision model typed choice, score and yes/no questions about a piece of content and get calibrated probabilities back instead of generated text, via /v1/decision-model/completions or the TypeSafe-compatible /v1/systemone'
---

A decision model answers typed questions about a piece of content, called the `state`, and returns calibrated probabilities instead of generated text. One request can ask many questions about the same state. Each answer comes back under the name you gave its question.

There are three question types:

- **choice** picks one option from a set you define.
- **score** rates the state against ordered levels.
- **noul** gives the probability that a yes/no statement is true.

## When to Use a Decision Model

| Use a decision model for | Use an [agent](/docs/documentation/capabilities/agent) for |
|---|---|
| Routing, labeling, scoring or flagging content against options you define | Writing, summarizing, extracting or rewriting text |
| Decisions you want to threshold on a probability, such as "send to a human below 0.6 confidence" | Open-ended answers with no fixed set of outcomes |
| High-volume checks where cost per item matters: input is \$0.0483 per 1M tokens on the `jev` models and output is free | Work that needs tools, search, MCP or several reasoning loops |
| Gating an agent call: decide first whether a task needs one at all | Anything where the output itself is the product |

## Endpoints

| Method | Path | What it does |
|---|---|---|
| `POST` | `/v1/decision-model/completions` | Swarms format. Returns the answers with a `job_id`, the model that answered, and `usage` with tokens and cost. |
| `POST` | `/v1/systemone` | The TypeSafe API's exact request and response format, so the official TypeSafe SDKs work against the Swarms API. |
| `GET` | `/v1/decision-model/models` | The available decision models and their prices. |
| `GET` | `/v1/models` | Unchanged for OpenAI clients. A request carrying the TypeSafe SDK's `X-TypeSafe-SDK` header gets the decision model list instead. |

All four are served from `https://api.swarms.world`. Send your API key as `x-api-key`, or as `Authorization: Bearer <key>`.

## Question Types

Every question has a `type`, optional `instructions` (text, a JSON object or a list), and `criteria` whose shape depends on the type.

| `type` | `criteria` | Answer fields |
|---|---|---|
| `choice` | **Required.** An object mapping each option name to a description of when it applies, or to `null` to go by the name alone. | `choice` (the picked option), `confidence`, and `probabilities` keyed by option |
| `score` | **Required.** A list of level descriptions, ordered from lowest to highest. A level's position is its score, starting at 0. At least one level. | `score` (the expected level, which can fall between levels, such as `1.58`), `confidence`, `legend` mapping each level to its description, and `probabilities` keyed by level |
| `noul` | Optional. An object with `true` and/or `false`, describing what counts as a yes and as a no. No other keys are accepted. | `noul`, the probability from 0 to 1 that the statement is true |

A `noul` question needs `instructions`, `criteria`, or both. A `choice` with an empty `criteria` object is rejected with a 400.

## Decision Model Completions

`POST /v1/decision-model/completions`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `model_name` | `string` | No | `"jev-latest"` | The decision model that answers the questions. Also accepted as `model`. |
| `state` | `string`, `object` or `array` | Yes | | The content every question is asked about |
| `questions` | `object` | Yes | | At least one question, keyed by a name you choose. Answers come back under the same names. |

### Response

The response to the curl request above:

```json
{
  "job_id": "decision-model-3f9c…",
  "status": "success",
  "model_name": "jev-latest",
  "model": "jev-1.13.0",
  "answers": {
    "department": {"type": "choice", "choice": "technical", "confidence": 0.98, "probabilities": {"technical": 0.99, "sales": 0.0, "billing": 0.01}},
    "frustration": {"type": "score", "score": 1.58, "confidence": 0.37, "legend": {"0": "Calm", "1": "Frustrated", "2": "Angry"}, "probabilities": {"0": 0.0, "1": 0.42, "2": 0.58}},
    "is_urgent": {"type": "noul", "noul": 0.97}
  },
  "usage": {"input_tokens": 421, "output_tokens": 73, "total_tokens": 494, "input_cost": 2.03343e-05, "output_cost": 0.0, "total_cost": 2.03343e-05},
  "timestamp": "2026-10-03T13:47:56.151066+00:00"
}
```

| Field | Type | Description |
|---|---|---|
| `job_id` | `string` | Unique identifier for this completion |
| `status` | `string` | `"success"` when the completion finished |
| `model_name` | `string` | The decision model you requested |
| `model` | `string` | The model version that answered, which can differ from an alias such as `jev-latest` |
| `answers` | `object` | Answers keyed by question name, with the fields listed in [Question Types](#question-types) |
| `usage` | `object` | `input_tokens`, `output_tokens` and `total_tokens` as reported by the provider, plus `input_cost`, `output_cost` and `total_cost` in USD. `total_cost` is the amount charged. |
| `timestamp` | `string` | ISO 8601 time the completion finished |

The completion response also carries the `x-typesafe-request-id` and `x-swarms-total-cost` headers described below.

## TypeSafe-Compatible Completions

`POST /v1/systemone` takes and returns exactly what TypeSafe's API does, so the official TypeSafe SDKs (`typesafe-sdk` on PyPI, `@typesafe-ai/sdk` on npm) work with `base_url="https://api.swarms.world"` and a Swarms API key. It is billed the same way as `/v1/decision-model/completions`.

- **Request:** `model` (required), `state` and `questions`. There is no `model_name` alias on this route.
- **Response body:** only `model`, `answers` and `usage`, where `usage` has `input_tokens` and `output_tokens`.
- **Response headers:** the job ID is in `x-typesafe-request-id` and the amount charged, in USD, is in `x-swarms-total-cost`.

```bash
curl -i -X POST "https://api.swarms.world/v1/systemone" \
  -H "Authorization: Bearer $SWARMS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-latest",
    "state": "I was charged twice. Please help.",
    "questions": {
      "billing": {"type": "noul", "instructions": "Is this about billing?"}
    }
  }'
```

```python
import os

from typesafe_sdk import Choice, Noul, TypeSafeClient

client = TypeSafeClient(api_key=os.environ["SWARMS_API_KEY"], base_url="https://api.swarms.world")
print([m.name for m in client.models.list().models])

result = client.system_one(
    state="I was charged twice. Please help.",
    questions={
        "billing": Noul(instructions="Is this about billing?"),
        "tone": Choice(instructions="What is the tone?", criteria={"calm": None, "angry": None}),
    },
)
print(result.nouls["billing"].noul, result.choices["tone"].choice)
print(result.raw_http_response.headers["x-swarms-total-cost"])
```

The [TypeSafe SDK guide](/docs/examples/examples/typesafe-sdk-with-swarms-api) covers the JavaScript client, the async client and error handling.

### Differences from the TypeSafe API

| Behavior | TypeSafe API | Swarms API |
|---|---|---|
| Unknown question `type` | `400` | `422`, naming the field |
| `422` error entries | Echo the request back in `input` | No `input` echo |
| `release_date` in the model list | A date | An empty string |

## List Decision Models

`GET /v1/decision-model/models` lists the decision models this API can run, with their prices in USD per 1M tokens.

```bash
curl "https://api.swarms.world/v1/decision-model/models" \
  -H "x-api-key: $SWARMS_API_KEY"
```

```json
{
  "status": "success",
  "models": [
    {
      "name": "jev-latest",
      "description": "TypeSafe decision model. $0.0483 per 1M input tokens, $0.0 per 1M output tokens.",
      "release_date": "",
      "provider": "typesafe",
      "input_cost_per_1m": 0.0483,
      "output_cost_per_1m": 0.0
    }
  ]
}
```

Each entry has `name` (pass it as `model_name` or `model`), `description`, `provider`, `input_cost_per_1m`, `output_cost_per_1m` and `release_date`, which is always an empty string. The list only includes models whose provider is configured on the server, so treat it as the source of truth for what you can call.

`GET /v1/models` returns the same body when the request carries the `X-TypeSafe-SDK` header, which is what the TypeSafe SDKs' `models.list()` sends. Without that header, `/v1/models` returns the usual [OpenAI-compatible model list](/docs/documentation/capabilities/openai-compatible).

## Pricing

Decision models are billed per token, on the token counts the provider reports:

| Model | Input (per 1M tokens) | Output (per 1M tokens) |
|---|---|---|
| `jev-latest`, `jev-preview`, `jev-1.13.0` | \$0.0483 | Free |
| `clef` | \$0.276 | Free |
| `clef-flash` | \$0.1035 | Free |

- `total_cost` is `input_tokens × input price / 1,000,000` plus the same for output. The request above used 421 input tokens on `jev-latest`: 421 × \$0.0483 / 1,000,000 = \$0.0000203.
- There is no per-agent fee and no night-time discount.
- The same \$1.00 minimum balance as the other completion endpoints applies. At or below it, both completion routes return `402` before calling the model.
- Nothing is charged when a request fails.
- `clef` and `clef-flash` prices are read live from the provider when those models are configured. Call [`GET /v1/decision-model/models`](#list-decision-models) for the current prices.

## Errors

Both completion routes return the same status codes:

| Code | Meaning |
|---|---|
| `400` | The model is unknown (`{"detail": {"error_type": "api_usage_error", "message": "Unknown model: <name>"}}`), or the provider rejected the questions, for example a `choice` with empty `criteria` or a `noul` with neither `instructions` nor `criteria`. The provider's own error is passed through. |
| `401` | Missing or invalid API key |
| `402` | Credit balance at or below \$1.00 |
| `422` | The request body failed validation: a missing `state` or `questions` (or `model` on `/v1/systemone`), an unknown question `type`, a `choice` without `criteria`, a `score` with an empty `criteria` list, or a key other than `true` and `false` in a `noul`'s `criteria` |
| `429` | Rate limit exceeded. See [Rate Limits](/docs/documentation/resources/ratelimits). |
| `502` | The decision model provider is unavailable. Retry shortly. |

`GET /v1/decision-model/models` returns `401` and `429` under the same conditions.
